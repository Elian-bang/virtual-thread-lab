# 하네스 — 무엇을 어떻게 재는가

측정 도구가 틀리면 결과가 아니라 **잡음을 해석하게 된다.**
실제로 이 실험에서 값이 10배씩 튀었고, 원인은 전부 도구였다.
그래서 도구가 지키는 규칙을 따로 적는다.

## 구성

```
[부하 생성기]  ──HTTP──▶  [앱 컨테이너]  ──JDBC──▶  [MySQL]
 제약 없음                 --cpus=1                제약 없음
                           --memory=1g
```

| | 왜 이렇게 |
|---|---|
| 앱만 1 core 1GB | 이력서에 쓴 운영 제약과 같게. **재려는 대상만 묶는다** |
| 생성기는 제약 없음 | 생성기가 병목이면 잰 값이 앱 성능이 아니다 |
| MySQL 제약 없음 | DB 가 병목이면 실험이 오염된다 |

## 지키는 규칙 6개

전부 **실제로 틀렸던 것을 고친 결과**다. 미리 안 게 아니라 당해서 안 것이다.

### 1. 앱이 준비되기 전에는 부하를 걸지 않는다

`/actuator/health` 만 보면 안 된다. 1 core 에서는 health 가 200 을 줘도
JDBC 클래스 로딩과 Hikari 초기화가 안 끝나 있다.
**실제 측정 경로**(`/send` 또는 `/sleep`)가 200 을 줄 때까지 기다린다.

준비에 실패하면 `SKIPPED` 로 적고 **부하를 걸지 않는다.**
실패한 측정이 조용히 데이터에 섞이는 것이 가장 나쁘다.

### 2. 컨테이너 이름을 재사용하지 않는다

같은 이름으로 지웠다 다시 만들면 **Docker 내장 DNS 가 옛 IP 를 잠시 물고 있다.**
부하 생성기가 죽은 컨테이너나 **직전 조건**의 컨테이너에 붙는다.

DB 를 안 쓰는 `/sleep` 실행에 `connMax=10` 이 찍혀서 알아챘다.
매 실행 고유한 이름을 쓰고, **이름이 아니라 IP 로 붙는다.**

### 3. 스윕이 두 개 동시에 돌지 못하게 한다

두 스윕이 겹치면 서로 CPU 를 다퉈 값이 전부 못 쓰게 된다.
`mkdir` 잠금으로 막는다. (`pkill` 은 이 환경에서 동작하지 않아 믿을 수 없다.)

### 4. 에러 시 백오프한다

백오프 없이 재시도하면 **느린 앱이 에러 폭풍으로 바뀐다.**
그러면 재는 것이 처리량이 아니라 재시도 속도다. 20ms 쉰다.

### 5. 컨테이너가 죽었으면 값을 남기지 않는다

CF 모델은 Tomcat 200 + 비동기 풀 200 = **400 스레드**다.
죽은 실행은 `DIED` 로만 적는다. (`-Xss512k` 로 스택을 줄였다.)

> ⚠️ **정정 (2026-09-14)** — v1 은 "1GB 에서 실제로 죽는다 · `DIED oom=true`" 라고 적었지만, 기록된 중단 실행 3건은 모두 `oom=` 칸이 **비어 있고** 2건은 PLATFORM 이다. 죽은 원인이 OOM 이라는 기록은 없다.

### 6. 한 번 잰 값을 평균처럼 쓰지 않는다

조건당 **3회**. 표에는 중앙값과 **최소~최대**를 같이 적는다.
3회가 벌어지면 그 조건은 결론에 쓰지 않는다.

> ⚠️ **정정** — "벌어진다" 의 기준을 정하지 않았고, 반복 폭 14%·22% 인 조건을 결론 표에 썼다. 조건 순서도 무작위화하지 않았다. v2 에서 임계값과 순서 무작위화를 먼저 정한다.

## 워밍업

매 조건 앞 **15초를 버리고 20초를 잰다.**
JIT 와 커넥션 풀이 데워지기 전 값은 다른 것을 재는 것이다.

## 측정 항목의 신뢰도

| 항목 | 출처 | 신뢰도 |
|---|---|---|
| TPS · p50 · p95 · p99 | 부하 생성기 (앱 **밖**) | 보통 — 측정 종료 뒤 끝난 진행 중 요청까지 세어, 지연이 긴 조건에서 TPS 가 부풀려진다 (정정) |
| 플랫폼 스레드 수 | 앱 `/stat` | 보통 — 앱이 포화되면 응답이 늦다 |
| 커넥션 획득 대기 | 앱 `/stat` (Hikari) | 보통 — 위와 같음. 앱 시작부터 누적값이다 |
| pinning 횟수 | `-Djdk.tracePinnedThreads` 로그 | **낮음** — `grep -c onPinned` 는 로그 줄 수라 발생 횟수가 아니고, 로그는 컨테이너와 함께 지워진다 (정정) |

**핵심 지표(TPS·백분위)는 앱 밖에서 잰다.** 앱이 포화돼도 값이 왜곡되지 않는다.
`/stat` 은 보조 지표다. 못 받으면 `UNAVAILABLE` 로 적는다.
